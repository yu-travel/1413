# LC1258 上板调试记录（ID 读回 0x16/8A 故障全排查）

**日期**：2026-08-18
**芯片**：LC1258（SIMCHIP 国产 16 通道 24 位 Δ-Σ ADC），对应官方手册《LC1258数据手册2026最新版.pdf》V1.8
**现象**：4 片 LC1258 上电 ID 均读不回 0x8B，`monitor_init` 全部 fail，15 路电源监测无法采集
**结论**：三个根因叠加（寄存器 6 位地址前缀缺失 + DOUT 采样边沿错误 + 数据流提前一拍），已修复并上板验证

---

## 一、故障现象时间线

| 阶段 | 代码状态 | 上板实测 | 说明 |
|------|---------|---------|------|
| 1. 首版 | 无前缀、RREG=0x50、下降沿后采样 | **ID=0x16** | 0x16=0x8B<<1，整字节左移 |
| 2. 按厂商模板对齐 | +CS 两沿延时、+tWAKE 5ms、+全量写9寄存器、+回读校验、RREG 改 0x40、数据 <<1 | ID=0x16（无改善） | 模板对齐未触及采样边沿 |

| 4. E1~E5 对照实验 | 5 种采样点对比 | 见下表 | 定位 DOUT 真时序 |
| 5. E6 配方 | bit7 预取 + 下降沿采样 | **ID=0x8B，全部寄存器完整读出** | 根因确认，配方成功 |

## 二、诊断实验数据表（一次上板，6 组对照）

每片 ADC 复位后（不写配置）直接 RREG 读 ID=0x8B，不同采样点：

| 实验 | 采样点定义 | 读回 | 解读 |
|------|-----------|------|------|
| E1 | 上升沿后 delay_us(1)（高电平中段） | 8A | [B7..B1,0]：bit0 丢失（芯片最后一拍后停止输出） |
| E2 | 紧凑时钟，上升沿后 ~60ns | 8A | 与 E1 同类 |
| E3 | 下降沿后 delay_us(1)（低电平中段） | 00 | 下降沿数据窗口已过期（数据仅瞬间有效） |
| **E4** | **下降沿瞬间（SCLK↓ 后立即读）** | **16** | **=0x8B<<1：完整位流在下降沿输出，且比常规 SPI 提前一拍** |
| E5 | 上升沿瞬间（~60ns） | 00 | 数据窗口尚未到达 |
| **E6** | **命令字末下降沿预取 bit7 + 各下降沿瞬间采样 bit6..0** | **8B** | **全部寄存器完整读出：0A 83 00 00 FF FF 00 FF FF 8B** |

E6 读出的全部寄存器（与手册 V1.8 表20 默认值一致）：
```
CONFIG0=0A  CONFIG1=83  MUXSCH=00  MUXDIF=00  MUXSG0=FF  MUXSG1=FF  SYSRED=00  GPIOC=FF  GPIOD=FF(引脚电平)  ID=8B
```
> GPIOD 读回 FF 说明：寄存器值确为 00h（厂商确认），但读模式返回的是芯片 GPIO 引脚电平（GPIOC=FF 全输入、引脚悬空内部上拉 → FF），非寄存器内容，属正常现象，不参与校验。

## 三、根因定论（三个根因叠加，缺一不可）

### 根因 1：寄存器 6 位地址前缀缺失
- LC1258 寄存器地址为 6 位（A5A4 + A3A2A1A0），每次 WREG/RREG 前必须先发"高 2 位地址前缀命令"，否则读写失效
- 前缀命令字节（官方手册 V1.8 表18）：**0xB0**（A5A4=00）/ 0xB1（01）/ 0xB2（10）/ 0xB3（11）
- 本工程寄存器全部 00h~09h（A5A4=00）→ 前缀固定 **0xB0**；RDATA 通道数据读不需要前缀
- 注意：早期 LC1258.md 中前缀十六进制写为 0xA8~0xAB（与二进制列矛盾），以 PDF 表18 的 **0xB0** 为准

### 根因 2 + 3：DOUT 采样边沿错误 + 数据流提前一拍
- **厂商确认时序**：SPI 接口时钟输入——**上升沿输入数据（DIN）**，**下降沿输出数据（DOUT）**（即经典 SPI Mode 1：CPOL=0 / CPHA=1 从芯片视角）
- 实测发现 DOUT 数据流比常规 SPI **提前一拍**：**bit7 在命令字节的最后一个下降沿就已输出**，bit6..bit0 依次在后续 7 个数据时钟下降沿输出
- 且 DOUT 数据仅在下降沿**瞬间**有效（窗口极短）：下降沿后 ~50ns 可读（E4），~1µs 后已为 0（E3）
- 因此：
  - 上升沿采样（E1/E2）→ 漏 bit0（芯片最后一拍后寄存器空、DOUT 停止）
  - 下降沿后延时采样（E3）→ 窗口已过，全 0
  - 下降沿瞬间采样但起点晚一拍（E4）→ 整体左移一位
  - **正确配方（E6）**：命令字发完（SCLK 低）立即预取 bit7 → 每个数据时钟下降沿瞬间采样 bit6..0 → 补 1 空时钟完成 8 时钟帧

### 附：厂商模板 `<<1` 之谜（已解开）
- 103_1258 模板用 STM32 硬件 SPI `CPHA_1Edge`（**上升沿**采样），比芯片的下降沿输出**早一拍**，读回数据整体左移一位，所以厂商在 `readData` 中 `<<1` 软件补偿
- 我们的 E6 配方在**下降沿**采样，位流完整对齐，**不需要 `<<1`**（后续 RDATA 数据量程待上板复核）

## 五、正确时序协议（E6 配方，固化目标）

### 寄存器读（RREG）
```
CS=0 → 延时 → 发 0xB0（前缀）→ 发 0x40|addr（RREG, MUL=0）
→ 【命令字最后下降沿后立即采样 DOUT = bit7】
→ 7 个时钟: [SCLK↑ → __NOP → SCLK↓ → 立即采样 = bit6..bit0]
→ 补 1 空时钟完成 8 数据时钟帧 → CS=1
```

### 通道数据读（RDATA，0x30）
- 命令 0x30 后连续读 4 字节（状态 + 3 字节 24bit 数据），每个字节用上述配方
- 连续字节天然衔接：下一字节的 bit7 恰在上一字节补的空时钟下降沿输出，预取点自动正确

### 写（WREG）
- DIN 上升沿锁存（输入方向），保持原有时序不变，无需修改

## 七、经验教训

1. **国产芯片禁止直接移植 TI 参考驱动**：LC1258 与 ADS1258 寄存器大体兼容，但**高阶寄存器、芯片 ID、时序细节存在专属差异**（官方手册 V1.8 明确声明），必须以官方最新手册为准
2. **位操作 SPI 调试方法论**：一次上板做多采样点对照实验（E1~E6），比逐次单点试错高效得多——每组数据独立打印，全部现象拼起来即可定位
3. **厂商模板代码需批判性吸收**：模板的 `<<1` 和 0x7E 掩码表面看似"芯片特性"，实为其硬件 SPI 配置的补偿手段与 CONFIG0 合法值检查——理解根因后再决定是否沿用
4. **数据流"提前一拍"陷阱**：DOUT 从命令字节最后下降沿就开始输出 bit7，常规"命令后读 8 位"的框架会漏掉第一拍导致整体移位——预取（precap）是关键
5. **保持调试工具可复用**：ADC_REG_DUMP_TEST 宏开关的寄存器 dump 诊断保留，后续联调/回归可快速验证寄存器读写
